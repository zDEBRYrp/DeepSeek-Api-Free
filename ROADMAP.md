## Прикрепление файлов и фото (multimodal)

Статус: частично реализовано, требует проверки на живом клиенте (OpenCode / Kilo Code).

### Как работает сейчас
- Входящие картинки принимаются в `ChatMessage.images` (типы `image_path`,
  `image_base64`, `image_url`) и в мультимодальном `content` (список частей с
  `image_url`). См. `app/schemas.py`.
- `app/main.py:_save_images_to_tmp` сохраняет `base64`/`path` во временные файлы
  и возвращает пути.
- `app/browser_session.py:_attach_files` прикрепляет их к полю ввода DeepSeek через
  `set_input_files` (селектор `SEL_FILE_INPUT=input[type='file']`).
- Лимит `MAX_FILES_PER_MESSAGE` (по умолч. 5).

### Что проверить, если вложения «не работают»
1. **Шлёт ли клиент картинки вообще.** OpenCode отправляет фото в
   `/v1/chat/completions` (поле `images` или `content` с `image_url`)? Проверить
   логами входящего запроса. Если не шлёт — проблема на стороне клиента, не моста.
2. **`image_url` с http/файловым путём.** Сейчас тип `image_url` (не `data:...`)
   вызывает ошибку в `_save_images_to_tmp`. Если OpenCode шлёт ссылки/пути — мост
   падает. Нужно докачивать файл на стороне моста.
3. **Совпадение селектора ввода DeepSeek.** `input[type='file']` может быть скрыт;
   возможно нужна кнопка «скрепка/+». Если прикрепление молча не срабатывает —
   модель не видит фото.
4. **Типы файлов.** DeepSeek в чате, вероятно, принимает только изображения.
   Документы/текст, прикреплённые как файл, модель может не «прочитать» — проверить.
5. **Форматы/размер.** JPG/PNG/WebP и лимит размера у DeepSeek.
6. **Несколько файлов за раз.** `set_input_files([...])` — принимает ли DeepSeek пакет.
7. **Видит ли модель результат.** После отправки убедиться, что DeepSeek реально
   учёл вложение (ответ ссылается на него), иначе UI изменился.

### Что доделать, если сломано
- [ ] Скачивать `image_url` (http/remote/file://) на стороне моста во временный
      файл → `image_path` (в `_save_images_to_tmp`).
- [ ] Надёжное прикрепление: явный клик по кнопке скрепки, ожидание появления
      `input[type=file]`, ретрай при неудаче.
- [ ] Пробрасывать ошибку прикрепления клиенту (из `_attach_files` в ответ OpenAI
      как `error`), а не молча валить запрос.
- [ ] Поддержка `base64` для произвольных типов файлов, не только png.
- [ ] Конфиг/логирование входящих вложений для отладки (что именно пришло от клиента).
- [ ] Исходящий путь: если модель просит «прочитай файл X», он должен дойти до
      клиента через read/write-инструменты, а не только вкладываться в чат.
